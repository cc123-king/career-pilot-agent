# CareerPilot 求职项目升级

新增文档来源核对、简历与岗位结构化提取、岗位确认后评分、可选择的知识检索及 SQLite 历史。

## 文档核对与历史页面

运行 scripts/run_web.py，打开 /ui/ 的“文档核对与历史”。

1. 上传简历，填写公司、岗位和 JD；选择规则/结构化模型提取以及关键词/混合检索。
2. 提取结果先显示岗位技能、必需/加分分类、原文上下文和简历事实来源。
3. 逐项核对岗位技能：确为要求的选“确认要求”；误提取的选“排除误提取”并填写原因；未处理的保持“待核实”。保存核对进度；全部核对且至少确认一项必需技能后生成评分。
4. 根据原文勾选已确认的简历事实，保存并生成事实草稿。
5. 刷新历史记录，输入记录编号并恢复；草稿、已确认项、岗位正文、提取方式与检索方式会一起恢复。

规则模式无需模型，岗位要求应有独立的“任职要求”“加分项”标题及下一行的技能列表。
结构化模式将简历提取文本与岗位正文发给已配置模型，支持自然语言 JD；每个非空字段都要求能定位到连续原文，最多修正一次，失败后回退规则并提示。
无法识别必需技能、简历缺少技能/项目或存在无来源字段时，先请求补充，不产生新评分。
岗位技能分类需人工核对，尤其注意“无需/优先”等表述；来源相同不代表语义判断一定正确。

简历来源表显示字段、提取值、PDF 页码或提取页序、原文。DOCX 提取页序不等同于 Word 物理分页。
草稿只包含确认过的原文事实；改变岗位核对项或原因后必须重新保存核对；再次进入待核实状态会清除旧评分与草稿。排除项及原因完整写入报告和历史，不会无提示地改变评分分母。
匹配分数表示规则定义的技能覆盖，不是录用概率。原有 /api/career/analyze 和简历分析页保持兼容；自然语言 JD 推荐使用新的核对流程。

## 检索与证据

关键词检索可离线运行。混合检索复用项目已有的候选融合与重排，需要模型、Embedding 配置；无法配置或执行时报告错误，不会静默改为关键词。
确认后的分析保存实际检索模式、top_k、min_score、混合检索参数、pipeline_version 和知识引用来源。
实际配置与记录共用同一份参数；评测时可明确区分关键词/混合结果，不能混称为语义检索效果。

## 历史与接口

数据库默认 data/career.sqlite3，可用 CAREER_STATE_DB 修改。
新核对页保存简历提取文本、JD、事实来源、岗位确认项、分析报告、草稿与配置；上传知识分块也会保留。
原有 /api/career/analyze 不自动保存个人简历。旧核对记录仍可读取已有草稿和原评分；页面提示旧版规则，不会自动改写。v2 记录需重新核对岗位后计算新版分数；更早且没有岗位提取数据的记录需重新提取。

- POST /api/career/reviews 创建记录，支持 parsing_mode=rules/model、retrieval_mode=keyword/hybrid；不会立即评分。
- GET /api/career/reviews 列出历史。
- GET /api/career/reviews/{id} 读取完整记录。
- POST /api/career/reviews/{id}/confirm-job，提交 {"fact_ids":[确认的岗位事实编号],"exclusions":[{"fact_id":"排除项编号","reason":"至少3字的排除原因"}]}。未分类条目自动保留为待核实，返回 analysis=null；全部核对后分析。
- 返回 confirmed_job_fact_ids、excluded_job_facts、pending_job_fact_ids、job_review_complete、job_scope，历史恢复保留核对进度与排除原因。
- POST /api/career/reviews/{id}/confirm，提交 {"fact_ids":[简历事实编号]}，保存草稿。
- DELETE /api/career/reviews/{id} 删除记录。

未知编号、重复编号、确认/排除重叠及空排除原因会被拒绝。只有加分项、必需项仍待核实的情况保存为待核实，不评分；全部必需项均被排除时不能生成完整评分。校验或检索失败不会覆盖已保存记录。
当前为本机单用户演示，不提供多用户数据归属隔离。

## 容器与 CI

准备 .env 后执行 docker compose up --build，在 http://127.0.0.1:8001/ui/ 使用。
容器采用 Python 3.12，数据放在命名卷中；CI 仅跑离线测试。Docker 构建与 Linux CI 实际运行须单独验证。
与 SolarAI-X 同机运行时修改其中一个 compose 主机端口。

## v3 评分规则与技能名称

同时有必需与加分项时，权重为 70% / 30%；只有一组要求时，该组权重为 100%。均没有要求时旧兼容接口返回 0，新核对流程会要求补充并暂停评分。
报告显示适用权重和两组覆盖率；不存在的组显示“不适用”。100 分表示确认范围内全部技能有对应简历声明或项目技术栈记录，不是能力证明或录用概率。

明确别名表统一用于匹配、建议、面试及来源关联：如 Fast API / Fast-API / FastAPI、postgres / PostgreSQL、sklearn / scikit-learn。
仅映射明确等价名称；SQL 与 PostgreSQL、Java 与 JavaScript、C 与 C++ 保持不同。原简历和证据原文不改写。
历史报告保存评分与别名版本，v3 检索流水线版本为 career-review-v3。

如果候选人暂不具备岗位要求，应确认该项为岗位要求并保留在分母中。排除只用于人工纠正误提取，系统保留原因供复核，不自动证明人工理由正确。
