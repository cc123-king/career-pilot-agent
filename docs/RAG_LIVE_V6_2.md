## CareerPilot修复内容

1. 增加有引用候选回答恢复。首次有效判不足后，可以尝试构造答案；仍须通过原文、数值、逐陈述支持与原问题覆盖检查。格式或服务异常不直接恢复，不展示部分回答。
2. 真实大语料初测发现0/24完成：小语料阈值和字面得分压制了中英混合的语义候选。最终采用20候选、关键词/向量权重1:2的RRF、6个阅读窗口，不把排序分数当答案置信度。是否可答仍由证据检查决定。权重比较只使用开发组已有向量，未新增外部资料。
3. 相邻原始分块组成可追溯窗口，保留组成分块ID，不跨文档、来源、页码或提取方式；Embedding仍使用原始小分块，无新增向量调用。共享上下文上限为8000字符，避免句子或条件因切块丢失。
4. 分开的问句分别保留为恢复要求；缺少要求编号的候选在模型审核前拒绝。审核明确只看回答实际写出的结论，不能把引文中未写入回答的内容当成已回答。
5. 修复sqlite3等标识符数字被误判为新增数值；仍检查真实数量、单位及科学记数法。允许并验证审核中冗余的claim_id关联，其余未知字段仍严格拒绝。
6. 新恢复提示遗漏JSON声明，曾造成一次服务端请求拒绝。补齐声明和调用前检查，并增加回归，避免同类无效请求发出。阿里云JSON模式对提示中的JSON关键词有明确要求，见[官方错误码说明](https://help.aliyun.com/zh/model-studio/error-code)。本次拒绝的具体原始错误正文未保存，原因依据提示检查与修复后成功恢复定位。

小语料v6初测程序17/19通过，但1份漏答后半句被助手识别；最终v6.2为19/19完整回答。历史初测、失败输出与中断账本均保留，没有覆盖失败来制造分数。

## 仍保留的问题

- v6-tech-04：答案“JSONDecodeError”本身正确，所引片段仅定义异常及其基类，缺少无效输入会触发它的条件。需要更完整的引文支持。
- v6-tech-07：英文may need被表述成“仍需要”，应保留可能性和条件。
- v6-tech-14：英文might misbehave被扩写为“会导致内部实现异常”，应避免扩大确定性或新增具体故障描述。
- v6-tech-10：模型引用改写了RST标记，未通过逐字原文检查，保持阻断。
- v6-tech-16：模型所有子项supported=true，却把整体answerable设为false并增加未问的细节，保持阻断。
- v6-negative-12：模型试图给出部分回答且同时声明缺少日志保留天数，严格契约阻断；未展示无依据的真实天数。

这些记录说明逐字引用校验和模型自审都有实际局限。当前助手复核不能替代独立人工验收，也不能把辅助词命中当正确率。下一轮质量评估宜准备新题并进行独立复核，避免反复针对同一题集调提示。

## SolarAI-X的模型依据

公开数据来自[Perovskite Database v1.0.1](https://zenodo.org/records/5837035)，CC BY4.0。筛出697条有光谱测量依据的源记录，按论文和组分去重为149条记录。训练、验证和测试按论文分组，避免同论文记录交叉；30条测试的二次Ridge MAE为0.0270 eV，训练均值基线为0.1064 eV。

一次Ridge参考MAE为0.0281 eV且RMSE更低，不能宣称复杂模型全面领先。独立组分划分在自己的训练/验证组选择一次Ridge，14条测试MAE为0.0366 eV，不能冒充部署二次模型的跨组分结果。仅MAPbIBr家族满足当前质量和样本要求，另外三个家族继续不可用，没有新增物理实验。

12个真实任务同时验证原公式与公开测量方法。真实工具业务失败、越界和未知实验值均按预期处理，不能用连接错误冒充正确的模型不可用状态。
