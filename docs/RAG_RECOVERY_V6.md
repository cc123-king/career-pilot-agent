# v6 有引用候选回答恢复与规模验证

v5.1 的已知失败主要是候选原文已经包含结论，但模型在“是否可回答”的前置判断中反复误拒。v6 保留首次核验；首次有效判不足时，尝试直接生成有引用候选回答，再做原文、数值和原问题完整覆盖检查。首次响应无效或服务不可用时不进入恢复。

候选原文只证明出处真实，不预先宣称语义充分。恢复回答必须通过与普通路径相同的逐陈述支持检查和原问题覆盖审查，才能展示。缺少任何实质要求时可以返回明确资料不足，部分回答不展示。标准实际路径最多3次聊天请求；历史自定义客户端仍兼容旧路径。评测请求总账保留恢复运行的预算余量，不会自动重试或重置累计消耗。

新增公开技术语料以 CPython v3.12.7 六份官方库文档为来源，保留原 RST 内容、PSF许可、URL与哈希，结合12份原有指南组成34份文档、1218个分块。36道作者标注题包含24道可回答与12道无答案题，开发和冻结组各18道（各12正6负）。它们不是独立人工标注的数据。以前35题全部转为已知回归，单独统计。

当前两套依赖环境各422项回归通过。新增真实模型质量尚未测量；原来的87.5%完成率、误拒结果及15份助手复核都属于历史版本。

计划的新增真实范围：已知35题复用同模型向量与相同阶段响应，新增向量上限0、聊天上限140；新技术文档36题新增向量上限125、聊天上限144。均为text-embedding-v4/qwen-plus，SDK自动重试0。问题答案与标签不发给模型，不发送个人简历或运行数据库。

实际应用可用 `python scripts/run_web.py --knowledge-dir evaluation/technical_corpus --port 8019` 加载同一大语料。首次问答会构建向量索引，可能调用已配置的模型服务；本轮没有从该页面发送问题。
