# CareerPilot 面试演示与检索评测

对应 D 盘教学版项目。不修改 Word 简历；说明中的数据必须以实际生成报告为准。

## 一条命令保存证据

```powershell
cd D:\AgentProjects\career-pilot-agent
.\.venv\Scripts\python.exe -B scripts/collect_interview_evidence.py
```

脚本使用项目自己的 Python，保存到独立的 `data/reports/evidence-<编号>` 目录，不覆盖此前报告。
依次运行完整 pytest、旧 10 题基线、新 30 题评测和三个业务验收场景。
没有外部模型调用，不修改 `.env`，不上传代码或个人简历。
生成的 manifest 记录实际命令、返回码、测试数量和源码指纹；失败会保留日志并返回非零退出码。

## 新评测比原来多验证什么

- 保留原来的 `retrieval_cases.json`，另增 `benchmark_cases.json`，避免改变历史基线。
- 30 道作者编写的题，开发组和测试组各 15 道，每组 10 道可回答、5 道无答案。
- 包含同义改写、跨来源问题及有相似词但没有具体答案的难负例。
- 每道正例标注来源与原文锚点，自动检查标签确实存在于知识资料中。
- 对比 100、250、500 字符切片，top-k 为 1 或 3，阈值为 0.05、0.20、0.35。
- 每个检索模式只按开发组的证据覆盖和无答案空检索率选参数，再评估一次测试组。
- JSON 保存逐题返回片段、名次、分数、证据是否命中；Markdown 显示失败题，不隐藏问题。

切片使用现有段落聚合算法；本次没有新增重叠窗口或调整线上切片配置。
证据覆盖率是原文锚点匹配，不是模型答案正确率，也不是引用正确性评估。
两份指南较短，且问题与标签均由同一作者设计；分组不等于外部独立测试集。
以后添加更多文档或调整参数，应另建新版本评测数据，不根据已看到的测试组结果反复优化再宣称盲测。

## 可选的真实向量与混合检索对照

以下命令会调用配置中的 Embedding 服务，可能计费，仅在确认配置与费用后自行运行：

```powershell
.\.venv\Scripts\python.exe -B scripts/benchmark_retrieval.py --mode compare --allow-live-calls
```

对比关键词、余弦向量检索、RRF 融合、RRF 加分数重排序四种模式。
客户端复用现有 `.env` 中的模型配置；报告不保存 Key。
向量缓存仅在本次评测进程内复用，减少重复计费，没有新增持久数据库。
默认离线执行没有这四模式的真实效果报告，不能写成混合检索提升了多少。
各模式分数不同，应分别在开发组选择阈值；阈值不应被当作正确概率。

## 可讲的开发问题

### 找对文件不等于找对证据

原来的来源级指标只判断文件名，短知识库里容易显得效果很好。
补充原文锚点、同义改写和带关键词负例，分开统计来源召回、证据覆盖和空检索率。
结果用实际报告说明；如果仍有误召回，承认现有关键词与阈值方案的限制，而不是捏造优化百分比。

### 网页和接口各有一份内存知识

不同 Python 进程的全局变量不共享，上传资料可能只被其中一个入口看见。
项目把 Gradio 挂载到 FastAPI，同一进程复用分析与知识入口，并用上传后可检索的测试验证。
它适合本地演示，但重启后上传资料丢失，多实例仍需共享持久存储与用户隔离。

## 必须如实说明的边界

七节点固定顺序工作流不是七个大模型自主讨论；简历解析、评分、建议和面试题主要由规则生成。
向量使用配置的 Embedding 接口，不是 BGE；分数重排序不是 Cross-Encoder。
当前上传知识及向量索引在内存，D 盘这个版本没有 SQLite 投递管理或 MySQL 持久化。
OCR 流程有实现和离线接口测试，但实际识别质量需用真实文件另测。
