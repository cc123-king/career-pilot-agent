# 历史小型 RAG 检索基线

本页实测表保留扩容前两份指南、10题的历史结果。当前知识库已扩展为12份，新的评测入口与解释见 [v4说明](RAG_EVIDENCE_V4.md)。使用当前知识库重新运行旧命令会得到不同结果。

## 为什么要做

单元测试检查程序行为是否符合预期，检索评测检查真实问题能否找对资料。
两者都需要：程序可以没有报错，但返回了不相关的文档。

这一节不调用大模型，只评估本地关键词检索，也不会改动网页配置或读取网页临时上传的知识。

## 文件分工

- `evaluation/retrieval_cases.json`：固定问题、人工标注的标准来源。
- `src/career_pilot/rag/evaluation.py`：检索每道题、对照标准来源、计算指标。
- `scripts/evaluate_retrieval.py`：读取数据、运行评测、保存 JSON 报告。
- `data/reports/retrieval-evaluation.json`：默认基线的逐题结果。

`expected_sources` 为空数组表示：当前知识库没有回答这道题的资料。
不是指现实世界没有答案。例如，天气问题有真实答案，但这两份求职资料中没有天气信息。

## 运行

```powershell
cd D:\AgentProjects\career-pilot-agent
.\.venv\Scripts\python.exe scripts/evaluate_retrieval.py
```

独立的阈值对照实验：

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_retrieval.py --min-score 0.20 --output data/reports/retrieval-evaluation-score-020.json
```

默认取前 1 个分块，再过滤低于阈值的结果，与 `RAGService.answer()` 的先取 top-k、再过滤顺序一致。
代码不修改知识库、网页配置、API Key 或模型配置。
再次使用相同输出路径会覆盖那一份生成报告；比较不同参数时使用不同的 `--output` 路径。

## 指标

- 来源 Recall@k：每道有答案题，找回的标准来源数量 / 标准来源总数，再取平均。
- MRR@k：第一条正确结果排第 1，得 1；排第 2，得 1/2；前 k 条没有正确结果，得 0。只统计有答案题。
- 无答案问题空检索率：无答案题中，过滤后没有返回结果的比例。它不是模型拒答率。

同一文档多个分块不能重复增加来源召回率。没有某一类样本时，该类指标为 `null` / `N/A`，不是 100%。
当前每道有答案题只有一个标准来源，且默认 k=1，因此 Recall@1 和 MRR@1 数值相同。

## 本次实测

| 阈值 | 来源 Recall@1 | MRR@1 | 无答案问题空检索率 |
| --- | --- | --- | --- |
| 0.05 | 100% | 1.000 | 50% |
| 0.20 | 100% | 1.000 | 100% |

在 0.05 的基线里，“苏州明天具体气温是多少？”错误返回 `resume_guidance.md`，关键词分数约 0.1905。
提高阈值到 0.20 后，这条结果被过滤掉。本实验没有修改网页实际使用的阈值。

知识库只有 2 份文档，问题只有 10 道，且有答案题与原文用词接近。这是学习用的开发集，不是独立的业务测试集。
不能把这些结果写成“实际业务准确率 100%”。后续需要更多文档、同义改写、混合问题、难负例，以及未参与调参的测试集。
默认不使用 top-k=3，是因为知识库只有少量分块，返回大多数资料容易使召回率看起来很好。
报告中的文件指纹可以检查问题集或知识库是否发生变化，但复现时仍要保留原数据和代码版本。

## 面试问题

问：RAG 回答不准确，你会直接改提示词吗？

答：我会先检查检索结果和引用来源。如果资料找错了，优先检查切片、检索、重排序与阈值；
如果找到了正确资料，但回答仍不准确，再检查上下文拼装和生成提示词。
我会用固定问题集比较修改前后的召回、排序与无答案过滤表现，再用未参与调参的测试集验证，避免只优化演示题。

## 小练习

运行默认评测和 0.20 阈值实验，打开两份报告，找到 `unanswerable-weather`。
观察其 `retrieved` 字段如何从一条简历资料变成空列表。
然后思考：阈值再提高，会不会把正确但分数偏低的结果也丢掉？
