# API 异常与重试指南

## 异常分类

认证失败、参数错误、限流、连接超时和服务端错误应分别记录。认证失败与参数错误应先修复配置或输入，不应无条件重试。错误响应面向用户保留稳定错误码，服务端日志使用请求编号关联排查。

## 重试与副作用

重试次数与超时应由具体服务的配置和契约决定，本指南不规定统一次数或秒数。对限流可读取服务返回的等待提示，并设置有上限的退避。写入操作重试前必须有幂等键或其他去重机制，避免重复创建业务记录。

## 日志

日志记录错误类型、阶段、请求编号与耗时。不要记录完整密钥、个人简历或供应商异常响应正文。捕获异常后应保留可观测的失败状态，不能把空结果伪装成成功。
