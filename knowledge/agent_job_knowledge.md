# AI Agent 求职知识库

## Agent 项目应该展示的核心能力

一个可用于求职的 Agent 项目不能只有聊天页面。应当展示清晰的目标、可观察的状态、至少一个外部工具、结构化输出、异常处理和可以复现的测试。面试时需要说明模型在什么条件下决定调用工具，以及工具结果如何回到工作流。

## LangGraph 工作流设计

LangGraph 适合有状态、多步骤和存在条件分支的任务。常见组成包括 State、Node、Edge、Conditional Edge 和 Checkpoint。项目讲解时应该给出每个节点的输入输出，并说明为什么要使用显式工作流，而不是把所有要求塞进一个提示词。

## RAG 检索增强生成

RAG 一般包括文档加载、切分、索引、检索和生成。评估时应分别关注检索是否找对内容，以及生成是否忠实于检索结果。数据量较小时可以先使用词法检索作为基线，再升级到 Embedding 和向量数据库。

## 工具调用与可靠性

工具调用应当有明确的输入模型、输出模型、超时、重试和错误降级。涉及写数据库、发消息或付费操作时，应增加人工确认。Pydantic 或 JSON Schema 可以降低参数格式错误，但仍需处理工具本身失败的情况。

## 简历项目描述方法

项目经历应采用“问题—动作—技术—结果”的结构。只写真实完成的功能和真实测量的数据，不能为了匹配 JD 编造指标。没有量化结果时，可以写测试范围、通过的测试用例、支持的文件格式或已完成的接口数量。

## AI Agent 面试准备

常见问题包括 LLM、RAG、Tool Calling 和 Agent 的区别，状态如何流转，如何处理幻觉，如何做评测，如何管理 API Key，以及工具失败如何恢复。回答项目问题时使用背景、目标、职责、实现、难点、验证和复盘七个部分。

## Python 后端工程实践

Python 大模型应用常使用 FastAPI 提供接口、Pydantic 校验输入输出、pytest 做自动测试、SQLite 或 PostgreSQL 持久化。需要避免硬编码密钥和绝对路径，并通过虚拟环境与依赖文件保证项目可以复现。
